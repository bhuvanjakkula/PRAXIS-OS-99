# PRAXIS OS v0.8 — Organizational Digital Twin & Multi-Agent Institution

## Purpose
v0.8 makes the organization itself a first-class world model. The canonical twin owns persistent institutional entities and append-only events; agents receive authority-scoped views and propose actions, while v0.7 governance remains the only execution path.

## Institutional ontology
`organization`, `person`, `role`, `team`, `asset`, `process`, `money`, `technology`, `contract`, `policy`, `objective`, and `external_actor` are represented through `InstitutionalEntity(kind=...)`, with stable identity, ownership, and attributes. Objectives bind an owner to a metric, target, and priority.

## State and events
The twin emits immutable `InstitutionalEvent` records for creation, updates, objectives, and governed actions. `SQLiteInstitutionStore` durably appends events and saves named state snapshots. Simulations operate on deep-copied snapshots and never mutate canonical state.

## Multi-agent institution
`InstitutionalAgent` has specialty, institutional roles, and an authority set. `view_for()` restricts the world model exposed to an agent. `InstitutionCoordinator` rejects proposals outside authority and delegates accepted proposals to the governed action runtime. Agents therefore cannot bypass policy by writing institutional state directly.

## Cross-domain composition
The twin is designed to bind institutional entities to v0.2 graph nodes/evidence, v0.3-v0.4 quantitative models, v0.5 causal hypotheses, v0.6 grounded sources, and v0.7 governed capabilities. The current implementation provides the institutional kernel and extension seams; provider-specific connectors remain future work.

## Integrity note
During v0.8 work, repository verification showed the physical Git tree ended at v0.4 even though earlier conversation reports described v0.5-v0.7 as committed. v0.8 repairs this by adding concrete intelligence, grounding, action/governance, and institution modules to the repository and documenting the actual test count.
