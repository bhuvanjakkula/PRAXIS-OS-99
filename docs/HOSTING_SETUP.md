# Recommended hosting and providers — 2026-10-02

Prepared configuration: **Render Docker web service + managed PostgreSQL + worker**,
**OpenAI Responses API** for grounded analysis, and the existing **World Bank**
country/economy snapshots. No services, domain purchases or paid API calls have
been created by this task. The Render account, private Git repository connection
and OpenAI server secret must still be supplied.

## Reviewable deployment configuration

`render.yaml` provisions a proposed paid private beta in Singapore:

- Web API: `0.5c-512mb`, authenticated product entry point, private API docs,
  health check, 32 concurrent requests and migration before deployment.
- Outbox worker: `0.5c-512mb`, waits for the API migration to create the schema.
- PostgreSQL 16: `0.5c-1g`, 5 GB storage, external database connections blocked.
- Automatic redeployment disabled. Signing key generated by Render. AI key entered
  privately during Blueprint setup, never embedded in source or the browser.

These are starting sizes, not load-tested capacity. Review Render's actual cost
summary and region before creating resources. The configuration follows the
[Render Blueprint reference](https://render.com/docs/blueprint-spec) and
[Docker deployment instructions](https://render.com/docs/docker).

1. Put the **contents of the `praxis-os` folder** in a private Git repository;
   `render.yaml` and Dockerfiles must be at its root. The local repository has no
   configured remote. Exclude user databases, backups, `.env` and credentials.
2. Connect that repository to a Render Blueprint. Review its proposed resources
   and enter `OPENAI_API_KEY` in Render's secret environment field. To deploy
   without AI, set `PRAXIS_AI_PROVIDER=none` and remove the key prompt from the
   Blueprint first.
3. Let the migration run, then verify `/health` over HTTPS. Without a credential,
   `/v1/decision-models` must return 401 and `/docs` must return 404.
4. In the API service's private shell, issue a tenant-scoped expiring login token
   with `python -m praxis.product.manage issue-token`. Use the documented subject,
   tenant, role, lifetime and file-output options; keep the output file private.
   Sign in through **Connect securely**. See PRODUCTION.md for the exact command.
5. Create a disposable decision and open **AI analysis**. Confirm stored results,
   provider identity, citation checks, role/tenant boundaries and human review.
   Repeat the host-side backup/restore drill and invited-user checks in PRIVATE_BETA.md.

## Domain

Start with Render's assigned `onrender.com` hostname. The launcher reads
`RENDER_EXTERNAL_HOSTNAME` and adds it to the exact host allowlist, as documented
in [Render's default environment variables](https://render.com/docs/environment-variables).
No particular hostname or custom-domain availability is guaranteed here.

When you supply a domain you control, add it in the Render dashboard, follow its
DNS instructions and add the exact hostname to `PRAXIS_ALLOWED_HOSTS` on the API
service. Keep the assigned hostname for health checks until host validation is
confirmed. Verify HTTPS and redirects on the actual deployment.

## OpenAI connection

The adapter uses the [Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses)
and [strict structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
The initial configurable model is the documented
[`gpt-4.1-mini-2025-04-14` snapshot](https://developers.openai.com/api/docs/models/gpt-4.1-mini),
which supports Responses and structured output. It is an initial integration model,
not a claim of validated policy expertise. Change `PRAXIS_OPENAI_MODEL` only after
evaluating representative decision cases and confirming account access.

| Server variable | Prepared setting |
|---|---|
| `PRAXIS_AI_PROVIDER` | `openai` in Render, `none` in `.env.example` |
| `OPENAI_API_KEY` | Private server secret; no key supplied by this task |
| `PRAXIS_OPENAI_MODEL` | `gpt-4.1-mini-2025-04-14` |
| `PRAXIS_OPENAI_TIMEOUT` | 30 seconds per pass |
| `PRAXIS_OPENAI_MAX_OUTPUT_TOKENS` | 2500 per pass |
| `PRAXIS_AI_ALLOWED_CLASSIFICATIONS` | `public` source/document excerpts only |

Every user-triggered analysis makes three requests: proposer, critic and synthesis.
There are no automatic retries or tool calls. Incomplete output, refusals, invalid
JSON and unknown citations fail without saving a successful analysis. Provider
errors are sanitized. Decision revisions remain unchanged.

The **decision framing and query** are sent even when source classifications are
limited to public; do not put prohibited confidential content in that framing.
Allowing internal/confidential/restricted excerpts is an explicit operator setting.
Previous pass outputs are sent to later passes. A source excerpt is never treated
as an instruction or verified truth. The adapter requests `store: false`; this does
not itself establish zero data retention or a compliance agreement.

Configure budget alerts/spend limits in the OpenAI account before inviting users.
Per-pass token caps limit response size; they are not a total account-spend limit.
API access/billing is configured separately from this local project.

## Validation and limits

`python -m praxis.product.hosted preflight` checks supplied PostgreSQL, signing-key,
host and provider configuration without printing secrets or making network calls.
It does not validate account access, DNS, database connectivity, TLS or live model
behavior. Test requests use fake transports; no live API credentials were available.
Docker is unavailable locally, so Render image builds and Blueprint acceptance
must be verified at the target host/dashboard.

Existing local SQLite records are not automatically migrated into the hosted
PostgreSQL database. The World Bank snapshot remains a manually refreshed public
data source. IMF/UN/private systems and treaty/legal datasets remain separate work.
